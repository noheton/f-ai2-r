\section{The Executable Skill}\label{sec:skill}

A method that lives in a PDF of guidelines depends on humans
remembering to follow it. We package aiprov instead as a
\emph{skill}: a versioned bundle of instructions and tools that an AI
agent loads and operates. The method's rules become the agent's
operating rules: log your own activities, record claims at
\texttt{ai-confirmed} at most, never fabricate telemetry, and never
grant a human-only rung.

\textbf{ORCID-first setup.} Setup asks the human operator exactly one
question: their ORCID iD. A single command then seeds the graph,
resolves the operator's name and current affiliation from the public
registry (never guessed; if resolution fails, only the bare iD is
recorded), derives the instance IRI base from the git remote,
scaffolds continuous integration, and lays down a compilable
chapter-per-file paper skeleton whose author block is already filled
from the resolved identity. Later commands auto-detect the base from
the graph, so configuration never needs repeating
(Figure~\ref{fig:workflow}).

\textbf{CI as the deterministic build agent.} Every push validates the
graph server-side, renders the dashboard, regenerates the
AI-transparency disclosure, and compiles the paper to PDF, uploading
dashboard and PDF as build artifacts. The current version of the paper
is always available, and a conformance violation blocks the build. The
CI service itself is registered as a \texttt{ToolAgent}, and its green
runs are logged \texttt{Build} activities carrying artifact digests.

\textbf{Live preview as oversight affordance.} On request, the agent
republishes the current typeset build, together with the per-section
planning skeletons, to a stable preview URL after every editing round
(Figure~\ref{fig:environment}, right panel). Effective human oversight
of a fast-moving AI collaborator requires a continuously current view
of the deliverable, not a repository dig; the EU AI Act's
human-oversight expectation~\cite{eu-ai-act2024} becomes a
user-interface property of the workflow.

\textbf{Structure before prose.} The agent first lays down each
section's principal structure, its argument flow, evidence, and figure
and citation plan, as a reviewable skeleton; prose is a separate later
pass. The operator can contest structure cheaply before any prose
exists to defend it, and both passes are logged, so the audit trail
shows which structural decisions preceded which text. Two rungs of the
ladder were redesigned exactly this way during this experiment.

\textbf{Regulatory fit by construction.} The skill derives the EU AI
Act transparency statement from the graph itself
(Section~\ref{sec:meta}); disclosure is a build product, not an
authoring chore, and adopters inherit the mechanism with the
scaffolded paper skeleton.

\textbf{Worked example: analysing experimental data.} The workflow is
not specific to writing papers; consider a study like the static
resistance welding of carbon fiber-reinforced thermoplastic
composites~\cite{resistance-welding2024}, where welding trials produce
process logs (current, temperature profiles), non-destructive scans,
and destructive test results, and the outcome is a set of capability
claims. Setup is identical: one ORCID question seeds the graph and
registers the experimenters; the data-acquisition software and the
analysis scripts join as \texttt{ToolAgent}s, the AI assistant as an
\texttt{AIAgent}. Each raw measurement file is registered as a
\texttt{Source} and vendored with its content hash, so the access gate
of rung~4 holds the evidence for every downstream claim as immutable
bytes. Each analysis run is a logged \texttt{Build} activity that
\texttt{used} the raw sources and \texttt{generated} the derived
tables and figures, hashes included; CI reruns the analysis, so a
figure that cannot be regenerated from the recorded inputs fails the
build. AI-assisted interpretation is an \texttt{AuthoringPass} with
telemetry, and every finding, say, weld-seam continuity across a
parameter window, is a claim generated by the analysis activity and
attributed to its agent. The ladder then works exactly as in
Section~\ref{sec:method}: the AI may cross-check a claim against the
derived data and grant \texttt{ai-confirmed}; the experimenter
spot-checks the destructive-test table for \texttt{human-confirmed},
with the tooling handing over the vendored data on request; the
capability conclusions that carry the paper deserve
\texttt{human-read}. The disclosure statement and the report come for
free, and with the shepard integration of
Section~\ref{sec:conclusion}, raw data and provenance share one
backbone.

\textbf{Versioning the method.} The skill tree is the repository.
Released snapshots are immutable, changes are logged in a changelog,
and every activity binds the commit under which it ran, so the
meta-experiment can cite the exact method version in force at any
point. The same property makes the skill the transferable unit: the
bundle that wrote this paper is the integration payload for the
shepard fork of Section~\ref{sec:conclusion}. Conversations are part
of the record too: a transcript exporter renders the agent session to
a committed Markdown file after every turn, and activities link to it,
so the dialogue that shaped an artefact is as retrievable as the
artefact.
