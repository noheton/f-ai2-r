% 6.1 Self-report honesty — the graph is only as truthful as its writer;
%     mitigations: omit-don't-estimate, content hashes + commits bind
%     records to bytes, CI validation is server-side, human rungs cap
%     what an AI may assert about itself.
% 6.2 Worked incident: repository-is-the-process in practice — during
%     this meta-experiment, a working-directory mixup led the AI agent
%     to overwrite two committed manuscript sections with template
%     stubs (graph activity s09-incident). Version control surfaced
%     the unintended diff immediately; restoration was a one-command
%     revert to the committed state, and the incident is recorded in
%     the graph rather than erased. The lesson generalizes: with the
%     repository as the process substrate, AI mistakes are recoverable
%     and auditable events, not silent corruption — the same property
%     that makes contributions attributable makes errors reversible.
% 6.3 Why human-only rungs stay human — ai-confirmed is a machine
%     judgement with known failure modes \cite{ai-hallucination2023};
%     the ladder makes the judgement's author explicit instead of
%     laundering it.
% 6.4 Cost of the method — logging overhead per session; what the
%     meta-experiment measured (Table~\ref{tab:telemetry}). Telemetry
%     honesty in practice: this experiment's own report lacks token and
%     cost figures because the agent harness did not expose them — the
%     omit-don't-estimate rule leaves a visible gap where other reports
%     might show invented precision. The gap is itself a finding:
%     provider-side usage reporting is the missing infrastructure.
% 6.5 Skill drift — the method evolves mid-experiment (v0 -> v0.4 here);
%     immutable archives + changelog + per-activity commit binding keep
%     runs attributable to the exact method version.
% 6.6 Regulatory alignment — the EU AI Act's transparency rules
%     \cite{eu-ai-act2024} ask for disclosure and machine-readable
%     marking of AI-generated content; a provenance graph is exactly
%     that marking, and the generated disclosure statement (§ Ack.)
%     never lags the graph because CI derives it on every build.
%     Provenance-first authoring turns a compliance duty into a
%     by-product.
% 6.7 Generality — beyond papers: code, data pipelines, CAD models,
%     AAS submodels \cite{aas-part1-v30rc02}; what transfers
%     (invariants, ladder) and what is domain work (entity
%     subclasses). The AAS case is the bridge to §8's shepard outlook:
%     digital-twin ecosystems already assume machine-readable
%     semantics, so AI-work provenance slots in as one more submodel
%     concern.
% 6.8 The force multiplier cuts both ways — one operator ran method,
%     paper, and integration fork in parallel during this experiment;
%     the same multiplication, unaccounted, is §3's dilution engine.
%     The differentiator is not speed but auditability: fast work that
%     carries its record is distinguishable from fast noise. "Fast
%     paper, slow ideas" is the honest reading of this project — and
%     only the graph makes that reading checkable.
% 6.8b Practices that emerged (novel enough to name, small enough to
%     adopt tomorrow):
%     - Registry-fetched citation metadata: every BibTeX entry comes
%       from doi.org content negotiation, never typed from memory — a
%       concrete anti-hallucination discipline for reference lists
%       \cite{ai-hallucination2023, fabricated-citations2023}. The one
%       failure was infrastructural (a registry served malformed
%       BibTeX) and was caught by CI, not by a reader.
%     - Registry-resolved identities: the operator, acknowledged
%       colleagues, and co-authors enter the record via ORCID lookups;
%       never-fabricate extends from telemetry to social metadata —
%       names, affiliations, and credit are looked up, not guessed.
%     - Verified-before-cited: a reference cannot appear in the
%       bibliography without a ladder-backed source node; the
%       bibliography is a view of the graph, not a hand-maintained
%       list.
% 6.8c TRANSPARENT SELF-CITATION (name the practice) — not inflating
%     metrics, but declaring important influences: no-parentless-claim
%     FORCES citing one's own priors, because the lineage (§2.6) IS
%     the author's own repositories and specifications. Frowned upon
%     as metric gaming, unavoidable as provenance. Resolution:
%     transparency instead of omission — sources carry
%     aiprov:selfCitation, the report prints the ratio (here: 4 of 30
%     sources), and reviewers judge necessity per source rather than
%     suspecting the whole list. The test that distinguishes influence
%     from inflation: a transparent self-citation is load-bearing
%     (removing it would orphan a lineage or method claim) and points
%     at repositories and specifications rather than metric-bearing
%     venues — it declares descent, it does not farm citations.
% 6.9 The optimistic reading — what the multiplication buys is not
%     mainly volume: AI absorbing the tedium (registry lookups, hash
%     binding, conformance checks, build plumbing) can free human
%     attention for the two things machines do not supply — connecting
%     ideas and connecting people. This paper's own record shows that
%     division of labour: the human turns in the session log are
%     lineage, judgement, and acknowledgement; the AI activities are
%     verification mechanics. No guarantee, only a chance — but a
%     provenance graph is how one would check, later, whether the
%     chance was taken.
