\section{The aiprov Method}\label{sec:method}

\textbf{Model.} aiprov extends PROV-O with three agent classes
(\texttt{HumanAgent}, \texttt{AIAgent}, \texttt{ToolAgent}), four
activity classes (\texttt{AuthoringPass}, \texttt{AuditPass},
\texttt{Build}, \texttt{Repair}), and entity classes for artefacts,
claims, sources, transcripts, and prompts, where prompts are treated
as source code and bound to activities as plans
(Figure~\ref{fig:vocab}). Humans carry ORCID and affiliation; AI
agents carry model, version, provider, endpoint, context window, and
knowledge cutoff; tool agents cover deterministic actors such as CI
jobs. A prompt is hashed and bound with \texttt{prov:hadPlan} rather
than paraphrased; plan and transcript are not recoverable after the
fact if not captured when the activity runs.

\textbf{Telemetry.} Activities carry session and request identifiers,
token counts by class (input, output, cache, reasoning), sampling
parameters, cost, energy, and the tools invoked. One rule governs all
of it: omit, don't estimate. Absent telemetry is recorded as absent;
invented precision is worse than a visible gap. Reported and computed
values stay apart (a computed cost carries its price basis; energy
stays empty unless reported). The harness exposes no usage to the
agent, so token totals are aggregated afterwards from the provider
usage blocks of the session record. Generated artefacts
receive sha256 content hashes at logging time, and prompt files
receive prompt hashes.

\textbf{Invariant I: no parentless claim.} Every \texttt{aiprov:Claim}
needs a generating activity, an attributed agent, and a verification
state. The conformance validator treats violations of the first two as
hard failures, and its nonzero exit code is the entire integration
contract: the same command serves as a pre-commit hook, a CI gate, and
an auditor's first step.

\textbf{Invariant II: the verification ladder.} Rungs answer who
checked what (Table~\ref{tab:ladder}). Promotions must strictly climb
and are themselves logged as audit activities, so every rung a claim
or source holds has a recorded grantor. Disagreement is first-class: an
agent may \emph{refuse} a promotion, which changes no state but is
logged as an audit activity carrying the refused rung, so ``checked and
not convinced'' is distinguishable from ``never checked''. Rungs 5--6
are human-only; an AI-granted promotion to them is a validator hard
failure. Vendoring (rung~4) is not a verification statement: an unread
vendored copy proves nothing beyond \texttt{reference-resolved}. It is
the access gate that makes human verification feasible and durable:
\texttt{promote} refuses the human-only rungs unless the source is
vendored (path and hash recorded) or carries a clear access link, and
a human confirmation
against link-only material is flagged, since the audit target remains
mutable. At the top, \texttt{human-read} subsumes
\texttt{human-confirmed}: it asserts full-text familiarity \emph{and}
confirmation, because reading does not entail checking. The ladder
canonicalizes labels field-tested in
\emph{Obscurity-Is-Dead}~\cite{obscurity-is-dead} and hardened in
F(AI)\textsuperscript{2}R~\cite{fair2r-repo}; legacy names remain
machine-readable aliases (four in the alias table, three as
\texttt{skos:altLabel}), but the consolidation of ancestor graphs has
not been exercised.

\textbf{Commit binding.} An activity can only bind a commit that
already exists, and a commit cannot contain the graph entry describing
itself. The working discipline that follows: commit the artefacts,
record that commit's hash in the graph (commits bind to artefacts, not
to activities), then commit the graph update separately; the cost is one
extra commit per logged round. The two commits buy tamper evidence in
both directions: backdating a record would require rewriting published
git history, and quietly swapping an artefact would break its recorded
hash. Falsification is possible, but neither is silent; honest work is
cheap, dishonest work is loud.

\textbf{Multi-agent runs.} The package adds a fifth activity class,
\texttt{Orchestration}: a run declares its planned roles and agents; delegation uses \texttt{prov:actedOnBehalfOf}
and \texttt{prov:wasInformedBy}, and logger and validator refuse
sub-activities outside the declared plan. Each sub-agent logs into its
own shard of the graph, since parallel writers to one file overwrite
each other, and \texttt{provlog merge} unions the shards append-only
while keeping the human-only invariant across them: it refuses a bare
human rung, a demotion, an edit of the plan, and any new validation
failure. A per-orchestration report keeps a cascade from counting as
many independent AI activities. This is implemented and covered by
tests, and unreleased.

\textbf{The validator.} Conformance is a set of SPARQL checks over the
graph (Table~\ref{tab:checks}): the skill line prints \MChkSkill{}
checks, \MChkSkillFail{} of which fail hard, and the package prints
\MChkPkg{}, \MChkPkgFail{} of which can fail.

\textbf{Auditability operations.} \texttt{report} aggregates tokens,
cost, and rung distributions; \texttt{extract} computes the backward
closure of everything that contributed to chosen entities; a separate
script, \texttt{aiprov-dashboard}, renders the graph as a
self-contained offline ledger. Sources enter through open registries (Crossref, OpenAlex,
arXiv, DataCite): a search command sweeps them, and registration with
DOI verification promotes a source to \texttt{reference-resolved} only
if the registry actually resolves it.
